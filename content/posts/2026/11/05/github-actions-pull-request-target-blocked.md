## 概要

GitHubは2026年12月2日以降、GitHub Actionsの公開リポジトリにおいて`pull_request_target`イベントをデフォルトでブロックすると発表した。「ワークフロー実行保護(workflow execution protections)」という仕組みを通じて実装され、明示的に許可するアクションイベントポリシーを設定していない限り、フォークから送られたプルリクエストに対して同イベントが発火しなくなる。対象はGitHub Free、Team、Enterprise Cloudプランのパブリックリポジトリで、プライベート・内部リポジトリやGitHub Enterprise Serverは対象外となる。

## なぜブロックするのか

`pull_request_target`は通常の`pull_request`イベントとは異なり、プルリクエストのコードではなく**ベースリポジトリのコンテキスト**でワークフローを実行する。これにより、CI/CDに必要なシークレットや昇格した権限へのアクセスが可能になる一方、フォークから送られた信頼できないコードをチェックアウトして実行するよう誤って設定されたワークフローは、シークレットの窃取やパイプライン自体の侵害につながるリスクを抱えていた。GitHubはこのリスクを"that code could compromise your pipeline or steal secrets"と説明しており、今回のデフォルトブロックはこうしたサプライチェーン攻撃の典型的な侵入経路を塞ぐことを狙っている。

## 移行スケジュールと対応方法

GitHubは本格適用に先立ち、2回の「ブラウンアウト」期間を設けて影響を事前に確認できるようにする。具体的には2026年11月9日16:00〜18:00 UTCと11月16日16:00〜18:00 UTCの2回、試験的に強制を有効化し、対象ワークフローが実際に失敗する様子を確認できる。各ブラウンアウト終了後は通常の評価モードに戻り、12月2日から本格的な強制が開始される。

既存のワークフローで`pull_request_target`を利用しているプロジェクトの管理者には2つの選択肢が示されている。デフォルトのブロックルールをそのまま維持してリスクを排除するか、「アクションイベントポリシー」で同イベントを明示的に許可するかだ。許可する場合もワークフローファイルを指定して対象を絞り込む「ワークフローファイルターゲティング」の利用が推奨されており、必要なワークフローだけに許可を限定することで、過度に広い例外設定を避けられる。

## 今後の影響

`pull_request_target`はDependabotの自動承認や、フォークPRに対するコメント投稿・ラベル付けなど、正当な用途でも広く使われてきたイベントであり、デフォルトブロックへの移行は多くのOSSプロジェクトの運用に影響する可能性がある。管理者はブラウンアウト期間を利用して自分のリポジトリで該当イベントが使われているかを早期に把握し、必要であれば12月2日までにアクションイベントポリシーを設定しておくことが求められる。
