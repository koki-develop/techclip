## 概要

Gitプロジェクトは11月10日、合計6件の脆弱性を修正するセキュリティリリース(v2.56.1、および2.50.2から2.55.1までの各メンテナンスシリーズ)を公開した。最も深刻なのはCVE-2026-111760で、悪意あるリポジトリを再帰的にクローンするだけで任意コードが実行される恐れがある。影響はv2.27.0以降の全サポートバージョンに及び、GitHubとThe Hacker Newsはいずれも直ちに更新するよう強く推奨している。

## CVE-2026-111760の仕組み

この欠陥の核心はインデックス処理における整数切り詰めバグだ。極端に長いパスを持つエントリはGitの安全性チェックを通過してしまうが、実際にディスクへ書き込まれる際には短い名前に変換される。攻撃者はこの切り詰め後の名前を`.git`に設定できる。The Hacker Newsは「An extremely long path in a repository can pass Git's safety check, but Git then writes it to disk under a shorter name that an attacker can set to .git.」と説明している。通常Gitは`.git`フォルダをシンボリックリンクに置き換えることを拒否するが、新規にクローンされたサブモジュールでは`.git`がファイルであるため、この防御が機能しない。結果として、攻撃者はシンボリックリンク経由でサブモジュールの設定やフックを差し替え、再帰的クローン完了時に悪意あるコードを実行させることが可能になる。修正版では、長さが切り詰められる可能性のある極端に長いインデックスエントリパス自体を拒否するようになった。

## その他5件の脆弱性

今回のリリースではCVE-2026-111760以外に、リファレンス処理・署名検証・バイナリパッチ・マージ・インポート機能に関わる5件も修正されている。CVE-2026-113408はGitプロトコルv2のパストラバーサルの欠陥で、サーバーが未生成ブランチへのシムレフを広告する際にパストラバーサルを含む参照名を送り込み、意図した参照ディレクトリ外への書き込みを誘発できた。CVE-2026-114467は、Gitが署名は最大2つまでという固定長配列の前提を置いていたため、3つ以上の署名を持つタグをマージするとスタック破損を招く欠陥だった。CVE-2026-114469はバイナリパッチの展開サイズ制限(1GiB)を圧縮によって回避でき、領域外読み取りとクラッシュを引き起こす問題。CVE-2026-105437は大規模なマージ時、特に多数の競合と大きな`conflict-marker-size`属性が組み合わさった際にメモリ計算がオーバーフローし、ヒープ破損につながる欠陥。CVE-2026-114466はfast-importの`rewrite-submodules-from/to`と`export-pack-edges`機能にセキュリティ制限が欠けており、任意のファイル読み書きを許す問題で、`--allow-unsafe-features`を明示的に有効化しない限り拒否されるよう修正された。

## 推奨される対応

GitHubとThe Hacker Newsはいずれも、v2.27.0以降の全サポートバージョンのユーザーに対し、該当するメンテナンスシリーズの修正版へ直ちに更新するよう呼びかけている。即時更新が難しい場合の暫定的な緩和策としては、信頼できるサーバーからのみクローンする、再帰的クローンの代わりに非再帰的クローンを使う、信頼できない第三者のコンテンツをマージしないといった運用上の対策が挙げられている。サブモジュールを扱うプロジェクトは特にCVE-2026-111760の影響範囲が大きいため、CI環境やビルドパイプラインで外部リポジトリを再帰的にクローンしている場合は優先的な対応が求められる。
